# Maintaining the index

Run these commands from the repository root. The checked-in data records the October 15, 2026 research snapshot. Collectors retain the observation dates used for that run; review those dates and the response cache before starting a fresh survey.

## Rebuild the Markdown

Python 3.10 or newer:

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python scripts/build_index.py
```

The checked-in JSON metadata is sufficient to rebuild the Markdown without network access. Re-running collection scripts makes public HTTP requests. They cache responses in ignored `.cache/`; HTTP errors are also cached, so remove only a failed response's cache file before a deliberate retry. No API credentials are required by the collectors.

The main index is generated directly into `README.md`, between `BEGIN GENERATED WRITING INDEX` and `END GENERATED WRITING INDEX` comments. Edit the introduction above the marker normally; edit article metadata in `data/*articles*.json` and social entries in `data/social-posts.json`, then rebuild. The generator preserves the introduction and regenerates counts with the tables. There is no separate main index file.

The [second research pass](second-pass.md) documents GitHub/Gist discovery, recovered bylines, and the ten-year X/Twitter survey. `data/github-articles.json` and `data/second-pass-articles.json` contain curated bibliographic evidence; `data/social-posts.json` stores verified post IDs, thread continuations, and the public metadata endpoints used to verify them. These records are maintained from the cited sources and are not regenerated by the original collectors. Social entries have their own counts and do not inflate article totals. Use Gist creation dates only with their stated date basis; never substitute repository commit dates for unknown publication dates.

The separate talks table is generated from `data/talks.json`. Each entry needs a direct recording or slide deck, primary-source speaker evidence where available, and a date basis distinguishing event dates from video/slide publication dates. Preserve YouTube video IDs and query parameters. Pair slides with a recording only when source evidence establishes the match. Keep publisher-only attribution when an individual speaker is not identified. Marketing, launch announcements, community calls, and event listings without a surviving recording or deck are excluded. [Talks research notes](talks.md) record selection decisions and remaining leads. Talk counts remain separate from writing and social counts.

Collection entry points:

```sh
.venv/bin/python scripts/research.py
.venv/bin/python scripts/history.py
.venv/bin/python scripts/ceramic.py
.venv/bin/python scripts/threebox_history.py
.venv/bin/python scripts/external.py
.venv/bin/python scripts/supplement.py
.venv/bin/python scripts/mirror.py
.venv/bin/python scripts/listings.py
.venv/bin/python scripts/linked.py
.venv/bin/python scripts/build_index.py
```

Some supplemental metadata was extracted with a web reader after ordinary HTTP reads failed. Those observations are retained in the checked-in web and reader JSON files; the collection scripts do not regenerate them. Bibliographic metadata and URLs are checked in. Cached article bodies, environments, and temporary downloads are ignored.
